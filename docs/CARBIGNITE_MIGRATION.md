## Deliberate behavior boundaries

- The homepage is a design preview using the approved sample catalog. It is not a production inventory adapter: the actual product contract contains no carbon category or material/finish variants.
- Sample fitment/prices are disclosed beside the collection and inside product dialogs. Footer explicitly discloses AI-generated concept imagery.
- The account action opens an availability explanation rather than linking to a missing page or collecting credentials.
- The concept bag deliberately omits the reference checkout action: no working target order endpoint exists. Its subtotal is a preview calculation only.
- Normal desktop/mobile product dialogs use the approved one-panel layout. Very short windows/zoom can scroll the whole dialog to keep controls reachable rather than clipping them.
- Account/sidebar hover exceptions are retained in the scoped interaction stylesheet for later account work; no account page is claimed implemented.

## How the code fits together

The page renders React components. `Homepage` owns theme and the concept selection; it passes callbacks to the header, collection and dialogs. Clicking a card gives `ProductDialog` a typed product. Adding a selection stores only product ID, pattern and finish; displayed sample totals are looked up from the concept catalog. `Dialog` manages the browser's native modal lifecycle and restores focus when it closes.

No backend code is changed. The existing backend still validates requests with Zod, applies product operations in the service, and sends database queries through the repository. Keeping this boundary means reviewing the design cannot overwrite stock, alter database records or replace authentication with the reference Site's identity system.
